# 数据契约 v1

实现：`core/crates/engine/src/`，FRB 与 UniFFI 只转发同一 Rust 实现。所有 JSON 使用 snake_case、UTF-8，当前 schema_version 为 1。公共签名为字符串，以免各端生成器分别定义业务规则。

## 入口

| Rust 入口 | 入参 | 返回 |
| --- | --- | --- |
| default_settings | 无 | 完整默认 Settings JSON |
| validate_settings | settings_json | 成功 `{ok:true,settings:规范化设置,errors:[]}`；失败 `{ok:false,errors:[{field,code}]}` |
| compute_snapshot | settings_json、holiday_json、now_millis(i64) | 成功 `{ok:true,snapshot:{…},errors:[]}`；失败 `{ok:false,errors:[{field,code}]}` |
| compute_timeline | settings_json、holiday_json、start_millis、step_seconds、count，后三项均为 i64 | 成功 `{ok:true,snapshots:[…],errors:[]}`。失败与单点快照使用同一错误信封 |
| update_custom_countdown | settings_json、change_json、now_millis(i64) | 成功返回新 `settings`。失败返回字段错误，不写文件 |

now_millis 是调用方传入的 Unix UTC 毫秒，不能来自各算法内部的当前时间。工作日与目标日期均使用设置中的 IANA 时区；设备所在时区不参与业务规则。

## Settings

省略的顶层字段补为下列默认值。可选子对象只补表中明示的默认值，其他必填字段缺失、未知字段和错误 JSON 类型均拒绝。十进制输入必须是字符串，不能写成 JSON 浮点数。

```json
{
  "schema_version": 1,
  "time_zone": "Asia/Shanghai",
  "region": "CN",
  "retirement_date": null,
  "birth": null,
  "schedule": {"workdays": [1,2,3,4,5], "start": "09:00", "end": "18:00", "lunch": ["12:00","13:00"]},
  "salary": null,
  "payday": null,
  "weekly_rest_as_holiday": true,
  "date_overrides": {},
  "holidays": [],
  "custom_countdowns": [],
  "hide_amount": true
}
```

| 字段 | 约束与语义 |
| --- | --- |
| region | CN/US/JP/KR/HK/TW；当前六地区基础周工作日均为周一至周五，法定假日数据不在本节点内置 |
| retirement_date | null 或公历 YYYY-MM-DD；以该日设置时区 00:00 为退休时刻，用户直接填写 |
| birth | `{date,time?,life_expectancy_years}`；寿命为 1–150、至多一位小数的字符串。出生时刻默认 00:00，寿命默认 `"100"` |
| schedule | ISO 星期 1–7，可选任意不重复子集；start < end，禁止跨夜；lunch 为 null 或位于工作区间内且起点早于终点的二元组 |
| salary | `{gross_monthly,net_monthly?,currency?,precision?,basis?}`。金额为非负十进制字符串，precision 允许 2–4 位，默认 2。basis 默认为 gross，net 需要提供税后月薪。币种允许三位大写代码，缺省取地区币种 |
| payday | `{rule,days,adjustment}`；fixed_day 一项 1–31、last_workday 空数组、twice_monthly 两项不同的 1–31；adjustment 为 next_workday/previous_workday/none，默认 next_workday |
| weekly_rest_as_holiday | 默认 true。关闭后仅排除全段为纯每周休息的区间 |
| date_overrides | 日期 → bool，true 为工作日、false 为休息日 |
| holidays | `{name,start,end,kind}` 数组；起止日期包含边界、start ≤ end、名称非空；当前所有自定义假期均作为休息日，不表示带薪/无薪 |
| custom_countdowns | `{id,name,target,enabled?,order?}` 数组。ID 唯一且非空，名称非空，target 为设置时区的本地公历日期时间。enabled 默认 true，order 为可选 u32 |

当前 UI 仅编辑退休日期与时区，保存时保留其余已知字段。移动 widget 只读取退休字段；不显示自定义倒计时或金额。

## 日历输入与优先级

无数据使用 `{}`。有数据的结构：

```json
{"schema_version":1,"region":"CN","years":[2026],"date_overrides":{"2026-11-07":true,"2026-11-09":false}}
```

上述为合成验收样例，不是法定日历。只有 schema、地区及年份匹配才使用地区日期覆盖。覆盖优先级：**个人日期覆盖 > 自定义假期 > 地区日期覆盖 > 每周工作日**。重叠自定义假期都表示休息日；无额外优先级。工作周中七天可任意勾选。

缺地区/年份数据时仍使用个人覆盖、自定义假期和工作周，calendar_status 为 weekly_fallback；匹配数据为 available。当前产品固定传 `{}`，不会假装已经有法定节假日。数据来源、数据修订号、下载/缓存/授权均由节点 06 负责。

## Snapshot

节点 03 和 04 逐步补齐 v1 的六类内置指标与自定义倒计时。原有退休对象、单点返回信封和原有 FRB/UniFFI 入口保持原格式。

```json
{
  "schema_version": 1,
  "computed_at_millis": 1793764800000,
  "local_date": "2026-11-04",
  "time_zone": "Asia/Shanghai",
  "is_workday": true,
  "calendar_status": "weekly_fallback",
  "next_change_at_millis": 1793768400000,
  "life": {"status": "unconfigured", "target_millis": null, "remaining_seconds": 0, "remaining_days": 0},
  "work": {"status": "lunch_break", "target_kind": "lunch_end", "target_millis": 1793768400000, "remaining_seconds": 3600, "remaining_days": 0},
  "retirement": {"status": "active", "target_millis": 1793808000000, "remaining_seconds": 43200, "remaining_days": 1},
  "payday": {"status": "unconfigured", "target_date": null, "target_millis": null, "remaining_seconds": 0, "remaining_days": 0},
  "holiday": {
    "status": "upcoming",
    "target_millis": 1793959200000,
    "remaining_seconds": 194400,
    "remaining_days": 2,
    "interval": {"first_rest_date": "2026-11-07", "last_rest_date": "2026-11-08", "start_millis": 1793959200000, "end_millis": 1794153600000},
    "next_interval": null
  },
  "calendar_remaining": {"life": null, "retirement": {"years": 0, "months": 0, "days": 0, "hours": 12, "minutes": 0, "seconds": 0}},
  "salary": {"status": "unconfigured", "currency": "CNY", "precision": 2, "basis": "gross", "hidden": true, "scheduled_workdays": 0, "today_earned": null, "month_earned": null},
  "custom_countdowns": [],
  "unavailable_metrics": []
}
```

| 指标 | 状态和附加字段 |
| --- | --- |
| life | `unconfigured`、`active`、`exceeded`、`out_of_range`。超出公历或可表示时间时无目标 |
| work | `rest_day`、`before_work`、`working`、`lunch_break`、`after_work`。有目标时 `target_kind` 为 `work_start`、`work_end` 或 `lunch_end` |
| payday | `unconfigured`、`no_target`、`upcoming`、`today`。有目标时 `target_date` 为设置时区的公历日期，整天保持 `today` |
| holiday | `no_target`、`upcoming`、`on_holiday`。返回当前或下一段休息 `interval`。正在休假时 `next_interval` 给出再下一段。无前后工作日的端点为 null |
| retirement | `unconfigured`、`active`、`retired`。设置日期的本地午夜为目标，达到目标时保持非负 |

所有指标的 `remaining_days` 是目标日和当前日的日历差。绝对剩余秒数向上取整，跨夏令时的一天可以是 23 或 25 小时。无目标时 `target_millis` 为 null，状态与合法的零倒计时有明确区别。`calendar_remaining` 提供生命的年/天/时/分/秒及退休的年/月/天/时/分/秒，供视图按需格式化。`next_change_at_millis` 是未来最早的工作状态、指标边界或本地换日时刻，数值仍可在该时刻之前随 now 减少。

### 节点 03 计算口径

- **小数寿命**先加整年并将非闰年的 2 月 29 日夹到 2 月 28 日。小数部分乘整年生日与下一年生日之间的实际公历日数，再以本地民用时间加到生日时刻。2000-02-29 00:00 加 25.5 年，得到 2025-02-28 00:00 加 182.5 天，目标为 2025-08-29 12:00。
- **工作状态**从绝对时钟计算。工作中显示距离下班，刷新边界可以早于下班，例如进入午休。休息日和下班后找下一实际工作日上班时刻。
- **发薪日**短月夹到月末，休息日按规则调整。每月最后工作日直接从工作日历取值。调整前后跨月、或两笔名义日期映射到同一日时，以实际日期为准。
- **放假段**合并连续实际休息日，从上一工作日下班开始，在下一工作日当地 00:00 结束。关闭每周休息计入开关时，纯周休不纳入；与显式假期相连的休息日仍合并。找不到下一工作日时，结束时间为 null。

## 节点 04 薪资、自定义倒计时与时间线

### 薪资

- 默认地区币种依次为 CN/CNY、US/USD、JP/JPY、KR/KRW、HK/HKD、TW/TWD。显式设置的币种保持原值。
- 按设置时区选当月。依工作日历计算有有效工时的应出勤日数，完整工作日均分月薪。当日按绝对毫秒经过量扣除午休，再除以该日的实际有效工时。夏令时改变有效时长，同一月的日薪份额保持一致。
- 今日已赚为当日份额，本月已赚为已结束工作日份额与今日份额之和。每次按当前配置和 now 重算。零应出勤日返回零。
- 使用 Decimal 尾数和整数比例计算，今日与本月分别在最终输出时向下截断为固定 2–4 位字符串。本月累计使用未截断的中间份额。旧版解析可接受但超过 Decimal 小数容量的尾数向零截断。
- 状态为 `unconfigured`、`no_workdays`、`earning` 或 `paused`。未配置时金额为 null。已配置且 `hide_amount` 为 true 时，快照和时间线仅输出 `****`，不带真实薪资或未遮蔽的派生金额。后续临时查看使用应用内存副本，长期共享偏好保持独立。

### 自定义倒计时

- 快照按 order 升序，省略 order 时使用原数组的零基下标，相同键保持原顺序。每项返回 `id`、`name`、`enabled`、`order` 与状态、目标毫秒和非负剩余时间。显示开关由桌面展示层消费，快照保留隐藏项供设置使用。
- 状态为 `active`、`expired` 或 `out_of_range`。目标进入 `next_change_at_millis` 候选。DST 跳时与重复时间沿用同一时区解析，读入已到期旧配置仍有效。
- 用 `{"action":"upsert","item":{"id":"launch","name":"产品上线","target":"2026-11-06T09:00:00"}}` 创建或替换。新增 ID 的目标必须严格晚于 now，否则返回 `target_not_future`。同 ID 编辑保留已有顺序位置，已到期项也可以编辑。用 `{"action":"remove","id":"launch"}` 删除，可安全重试。
- 变更接口只返回内存配置。保存、重启加载和 UI 操作分别由后续节点接入，移动原生退休组件当前只渲染退休字段。

### 时间线

- 首项为 `start_millis`，第 i 项为 `start_millis + i × step_seconds × 1000`。步长必须为正，count 取 1–1440。所有项复用同一份已校验配置与日历。
- 检查算术溢出、日历边界与 8 MiB 响应体限制。失败返回完整错误信封，不返回部分结果。核心按显式输入同步计算，刷新调度由宿主负责。

## 时区、错误与兼容

- jiff 0.2.39 启用 tzdb-bundle-always，四端使用锁文件固定的时区数据库，避免依赖手机/桌面系统数据库。时区更新随应用核心版本发布。
- 用户填报的退休午夜存在重叠或缺失时，继续返回 `ambiguous_local_time`。生成的工作、发薪、生命与放假时间遇到重叠取第一次，遇到跳时取时区转场时刻。下一换日边界必须在 now 之后。
- 验证失败只返回字段路径和稳定错误码，不携带原始个人值；计算阶段对非法设置返回 settings/invalid_settings。常用码：invalid_json、too_large、unsupported_version、invalid_date、invalid_time_zone、invalid_workdays、invalid_work_hours、invalid_lunch、invalid_amount、invalid_precision、invalid_paydays、net_salary_required、invalid_timestamp、out_of_range。
- Settings 上限 128 KiB，Android/iOS 共享读取有同样上限。未知字段由 Rust 拒绝，缺少字段时填入当前默认值。Flutter repository 将显式版本 0 的候选改为 1 后交给 Rust 校验，通过后备份原件并替换。
- 新安装没有主文件时加载默认设置。损坏文件保留原件，若有效备份可用则只读加载。用户选择恢复时，先把损坏原件归档再替换主配置。未来版本保留原件并禁止写入。
- 桌面使用同目录临时文件后 rename；Android 使用 AtomicFile 回滚；iOS 使用 App Group 文件 Data.write(.atomic)。无账号或配置上传。

固定时钟样例见[退休基线](../../core/testdata/retirement_cases.json)及[五类时间指标](../../core/testdata/time_metric_cases.json)。Android 集成测试用相同 now 比较 FRB 与原生 UniFFI 的完整响应。Apple 的 Swift 主机探测可在 Mac 验证固定退休样例。
