# 节点 12 主屏幕倒计时与薪资组件

前置版本为 `d947293`。实现版本以本报告所在提交为准。[节点计划](../../开发计划/12-iOS与Android小组件.md)

## 怎么检查

1. 长按主屏幕空白区域，打开小组件列表并找到时余，分别添加「倒计时」和「薪资」。支持固定组件的 Android 启动器也可从时余「设置 → 主屏幕小组件」请求添加。
2. Android 点击倒计时卡片可为当前实例选择上下班、放假、发薪或退休。在支持重配的启动器上也可长按选择编辑。缩小组件显示选定项，放宽且有足够高度后显示四项。
3. iOS 17 及以上长按「时余 · Countdown」后编辑主指标。iOS 15 和 16 在列表中选择固定主指标版本，切换时重新添加。中尺寸显示四项。
4. 薪资组件显示今日已赚和本月已赚。开启全局隐藏金额，两项应显示 `****`。组件没有临时显示真实金额的入口。
5. 退到系统桌面后查看倒计时走秒，删除组件后可以重新添加。配置属于组件实例，其他实例的选项保持各自独立。

## 刷新与边界

Android 以最近一次 Rust 快照显示完整倒计时。薪资存在时尝试约每分钟调度一次非唤醒闹钟，只有倒计时组件时最长约 15 分钟请求一次，已知业务边界可提前。Android 12 起由启动器选择响应尺寸。旧系统根据方向选择合适布局。

iOS 在 WidgetKit 允许时更新。倒计时在业务边界前后使用时间线条目，iOS 16 及以上最后一天使用系统计时显示。薪资仅生成当前值，约一分钟后申请下一次更新，避免未来条目继续保存先前的未遮蔽金额。

屏幕关闭、省电模式和系统预算均会影响刷新时机。组件显示距实际计算时间的间隔，关闭主应用的界面后仍使用共享文件独立调用 Rust。Android 从系统设置强行停止应用时，系统可暂缓广播或清除闹钟，重新打开应用可恢复调度。

Android API 36 x86_64 使用 Pixel Launcher。iOS 编译、签名、系统添加、iOS 15/16/17+ 差异，以及 Android 真机、最低 API 和其他启动器待复核。

仓库检查通过，含 22 项 Flutter 测试与 16 项 Rust 测试。Android 两项原生集成通过，覆盖固定时钟、日历、薪资精度与设置损坏、缺失和未来版本下的金额遮蔽回退。

在 Pixel Launcher 实际添加两种组件，将紧凑倒计时重新配置为放假，再将宽度从 3 格拉到 4 格，看到四项同时显示。薪资同时显示两个遮蔽值。关闭 Flutter 活动并用 `adb shell am kill` 回收进程后，Android 闹钟再次唤起原生进程，Launcher 仍为前台。一次观测中更新时间超过 90 秒，反映系统实际调度延迟。[Android 主屏幕截图](android-pixel-launcher.png)
