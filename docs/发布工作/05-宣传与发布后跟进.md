# 05 宣传与发布后跟进

先确定这轮是定向内测、公开招募还是正式发布。每条内容都写清读者能做什么、支持哪个平台、从哪里进入。

## 1. 备素材和文案

- [ ] 确认本轮版本、已开放平台、支持系统、实际可用链接和截止条件。制作一份中英文基础文案，测试邀请和正式上架分别写。
- [ ] 准备应用图标、一张主图和三到五张真实截图。优先展示猫猫倒计时、百岁功能和手机主屏幕组件，分别标注平台。英文宣传用英文界面截图。
- [ ] 用虚构生日、薪资和时间表录屏。发布前核对截图没有个人账号、真实薪资、后台页面或私有邀请信息。
- [ ] 如要做短视频，先录一条「从配置到添加主屏幕小组件」的完整路径。画面里涉及刷新时说明平台和系统版本。
- [ ] 列出本轮三项测试任务和反馈方式。建议任务为安装与首次启动、添加并编辑小组件、保存配置后重启确认。反馈模板收集平台、系统、版本、步骤和现象。

## 2. 分渠道发布

| 渠道 | 适用阶段 | 要交付的内容 |
| --- | --- | --- |
| 定向群聊或私信 | 内部或封闭测试 | 对应平台加入步骤、测试任务、反馈方式、有效期 |
| 个人站与个人社交账号 | 公开招募或正式发布 | 一张主图、当前开放平台、官网链接、测试或正式状态 |
| 小红书或 B 站等已使用的账号 | 公开招募或正式发布 | 图文或短视频展示实际使用场景，附官网或获准公开的报名方式 |
| 英文社交账号或相关社区 | 有英文材料和可用渠道后 | 英文简述与截图，附英文官网并遵守社区发布规则 |
| GitHub README / Release | 对应公开包或版本说明就绪后 | 版本说明、已知问题、公开安装入口和反馈链接 |

- [ ] 上表是候选渠道，先选现有账号中能维护的少数渠道，记录账号、文案、素材、发布时间和负责人。
- [ ] 发出前在手机上点一遍所有链接。公开内容优先引导到官网，让渠道变更能在同一处更新。仅限受邀账号的安装入口通过定向消息发送。
- [ ] 有开放内测时写清参与条件、可用设备和退出方式。商店页已上线并实装后，再发布对应平台的正式上线消息。

## 3. 发布后回查

- [ ] 发布当天复查帖子里的官网入口和首批安装。记录安装失败、链接权限、小组件找不到、系统版本不兼容等反馈。
- [ ] 次日检查公开链接、名额、构建有效期和反馈入口。遇到阻断时，在构建管理下架对应入口并更正已发宣传内容。
- [ ] 第一周汇总测试反馈。按阻断发布、需要修复、后续建议分组，把可复现问题写入项目 Issue 或对应验收记录。
- [ ] 保存发布记录。每条包含日期、平台、内容链接、使用的构建版本、网站入口、回查结果和后续处理。正式发布另记各平台获批及实际公开日期。
