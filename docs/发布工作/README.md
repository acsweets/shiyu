# 时余发布工作台

更新于 2026-11-06。先推进移动端内测，再按实际可安装的渠道更新官网和宣传。工程验收仍以[节点 13](../开发计划/13-全平台回归与性能稳定性.md)和[节点 14](../开发计划/14-签名打包与发布验收.md)为准。

## 现在先做什么

- [ ] 在 Windows 整理节点 13 的待提交代码，锁定一个验收 commit。当前工作区还有移动端、小组件和设置相关改动，Mac 需要拿到包含这些改动的候选版本。
- [ ] 在 Mac 用该 commit 跑 iOS 模拟器。先看应用能打开、保存设置后重启仍在、主屏幕小组件能读取配置。
- [ ] 用 iPhone 核对签名、共享配置和小组件。记录设备、系统、commit 和结果，再进入商店构建。
- [ ] 打开 Apple 和 Google 后台确认账号可用。创建应用记录可以与修复测试问题并行，首次上传要使用验收过的候选版本。

## 当前基线

- 仓库应用配置为 0.1.0+1。每次验收记录实际版本和 build number，后续上传按商店要求递增。
- Android 模拟器有 Release 验收记录，真机及商店签名构建待验。iOS 最新节点的真机与小组件验收待补。[节点 13 验收记录](../验收记录/13/README.md)
- 时余中英文官网已部署。当前公开构建接口尚无 slug 为 shiyu 的已发布记录，应用展示和各平台安装渠道需要分别在构建管理发布。[中文官网](https://xingverse.xyz/shiyu/) · [英文官网](https://xingverse.xyz/shiyu/en/) · [构建管理](https://xingverse.xyz/admin/builds)
- Windows 和 macOS 的公开包沿用节点 14 的安装、签名和兼容性验收。先完成的移动内测可以先行，其他平台按真实状态展示。

## 发布流水

每换一个候选就补一行。测试者账号和受邀链接留在对应后台或私有记录，仓库只记录受众和已确认可公开的地址。

| 平台与渠道 | 版本 / 构建号 / commit | 安装证据 | 受众 | 公开入口 | 状态 |
| --- | --- | --- | --- | --- | --- |
| iOS · TestFlight | 待填 | 待填 | 待确定 | 待填 | 待验 |
| Android · Play 内部或封闭测试 | 待填 | 待填 | 获准测试者 | 待填 | 待验 |
| Android · Google Play 正式版 | 待填 | 待填 | 目标地区用户 | 待填 | 待发布 |
| iOS · App Store 正式版 | 待填 | 待填 | 目标地区用户 | 待填 | 待发布 |
| Windows · 官网直链 | 待填 | 待填 | 待确定 | 待填 | 待验 |
| macOS · 官网直链 | 待填 | 待填 | 待确定 | 待填 | 待验 |

每次从后台发布或撤回渠道后，记录实际检查日期、执行人、访客安装结果和处理中的问题。渠道实装通过才进入官网更新，官网复测通过才使用该渠道做公开宣传。
