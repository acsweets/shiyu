# 桌面悬浮计时器最终开发步骤、排期与测试验证

版本：1.0  
日期：2026-11-04  
计划基线：MVP 冻结需求 1.0  
团队假设：2 名开发者；具备 Rust、Flutter、iOS/macOS 与 Android/Windows 构建条件  
估算：约 12 周开发 + 1 周发布缓冲；两人全职并行。若原生平台经验不足，或签名/数据源延迟，预计 14–16 周。

## 1. 执行原则

1. 以 [MVP-冻结需求-1.0.md](MVP-冻结需求-1.0.md) 作为唯一产品验收范围。未经版本化变更，不增加未冻结功能。
2. Rust 核心先定义稳定的数据契约；Flutter 桌面、移动端和原生小组件共享同一套计算结果与测试样例。
3. 提前验证高风险平台能力：透明/点击穿透/全屏浮窗、Rust 到 Flutter 绑定、iOS Widget Extension 链接、Android Widget 调用与共享数据。
4. 每阶段以可运行构建、自动测试和验收证据退出；不把“代码完成”当作阶段完成。
5. 主干保持可构建；生成绑定、节假日数据和皮肤资源均可通过可重复脚本再现。

## 2. 技术基线与开工前决策

### 2.1 技术基线

| 层 | 选型 | 责任 |
| --- | --- | --- |
| 计算核心 | Rust workspace、jiff、rust_decimal、serde | 时间、日历、薪资、六类内置指标及桌面自定义倒计时纯计算 |
| 桌面/移动 UI | Flutter、Riverpod、intl/ARB | 设置、浮窗、移动首页、状态、格式化与本地化 |
| Flutter-Rust | flutter_rust_bridge | 桌面和 Flutter 应用内调用 Rust |
| 原生小组件绑定 | UniFFI | Swift/Kotlin 调用同一 Rust 核心 |
| 桌面窗口 | window_manager；必要时平台原生桥接 | 无边框、透明、置顶、位置和尺寸；平台特性差异由原生适配 |
| 系统入口 | tray_manager；快捷键插件/平台桥接 | Windows 托盘、macOS 菜单栏、全局快捷键 |
| 存储 | JSON + path_provider；平台共享容器 | 应用设置、节假日缓存、App Group/Android widget 共享数据 |
| 小组件 | iOS WidgetKit/SwiftUI；Android Glance 或 RemoteViews | 系统约束下呈现倒计时与低频刷新的薪资 |
| 皮肤 | 声明式 JSON + 资源白名单 | 两套内置皮肤、timerpack 校验、导入/导出和安装 |

### 2.2 M0 必须锁定的技术决策

- Rust 与 Flutter 的具体稳定版本、最低操作系统 SDK、依赖锁文件和 CI 镜像。
- jiff 版本与 IANA 时区数据库更新策略；时间输入采用本地日期时间和 IANA 时区，核心函数由调用方显式传入 `now` 与时区。
- `Settings`、`HolidayData`、`Snapshot`、`next_change_at`、错误类型和 schema 版本；JSON 字段统一 snake_case 或 camelCase 并固定。
- flutter_rust_bridge 与 UniFFI 是否共用一个 Rust facade crate；绑定生成必须在 CI 可重复执行。
- 节假日数据源、六地区覆盖、许可证、更新 URL、签名/校验、数据版本和离线降级行为。
- macOS 全屏 Space 覆盖方案与分发方式；采用的私有 API 必须记录升级风险及不支持时的降级行为。
- `tray_manager`、`window_manager`、全局快捷键、透明窗口在目标平台的实际能力，不以插件文档替代设备验证。
- 自定义倒计时序列化字段和设置迁移；1.0 限桌面显示和管理，不进入移动小组件契约。

### 2.3 对旧文档的处理

旧技术方案/里程碑中的“移动端后续”“首批 12 个地区”“3 套皮肤”“Yearly/Hourly 薪资输入”等与 MVP 1.0 冲突。实施按本计划和 MVP 1.0 执行；这些旧段落留待单独统一，不能作为开发依据。不得将历史草案中的 `salary_type` 等已冻结排除字段直接带入最终数据模型。

## 3. 工程仓库和模块边界

建议仓库结构：

```text
workspace/
├─ core/
│  ├─ crates/engine/          # 无副作用纯计算
│  ├─ crates/ffi/             # UniFFI facade
│  └─ testdata/               # 跨语言黄金样例和节假日 fixtures
├─ app/                       # Flutter Windows/macOS/iOS/Android
├─ app/macos/                 # 全屏、透明、状态恢复原生适配
├─ app/windows/               # 窗口扩展、托盘/快捷键原生适配
├─ ios/Widget/                # WidgetKit 扩展
├─ android/widget/            # Glance/RemoteViews provider
├─ assets/holidays/           # 经校验的数据文件
├─ assets/skins/              # 两套内置声明式皮肤
├─ docs/                      # ADR、签名、发布与测试记录
└─ scripts/                   # 生成绑定、校验数据、构建与打包
```

核心 API 建议最少包括：`validate_settings(settings)`、`compute(settings, holidays, now, time_zone)`、`timeline(settings, holidays, start, interval, count)`。`compute` 返回完整 `Snapshot`，包含有效状态、展示原始数值、币种/精度信息、下一变化时刻及可诊断但不含敏感值的错误。格式化、排序和皮肤布局在 Flutter/原生视图层，不放入计算核心。

### 4.1 阶段门禁

- **G0（第 1 周）**：Windows、macOS 悬浮窗基础 spike 成功；iOS Widget Extension 和 Android Widget 至少能编译运行并读取 Rust 结果；全屏策略和降级写入 ADR。失败项形成有范围影响的决策，不得静默延后。
- **G1（第 4 周）**：Rust API、schema、黄金样例和计算测试通过；UI 后续不得复制业务计算。
- **G2（第 8 周）**：桌面 MVP 功能齐全，平台窗口、托盘、快捷键、数据/皮肤导入均通过；冻结桌面特性。
- **G3（第 10 周）**：两种移动平台小组件接入统一核心，离线共享数据通过；平台刷新限制明确呈现。
- **G4（第 11 周）**：无 P0/P1 缺陷，性能与长稳目标通过；进入发布候选。
- **G5（第 12 周）**：签名、公证/安装包校验、最终验收与回滚演练通过。

## 5. 测试策略

### 5.1 Rust 核心测试

- **单元测试**：各业务规则边界；日期/月末、闰年、生日加年、DST、时区变化；工作日覆盖优先级；午休边界；应出勤天数为 0；薪资精度与向下截断；三种发薪方式；连续休息段合并；自定义倒计时到期。
- **属性测试（proptest）**：剩余时间不为负；同一输入确定性；日期推进不会使目标变化无因倒退；金额在有效工作时间单调不减，在暂停区间不变；时间改变后结果由绝对时间重算。
- **黄金测试**：共享 JSON 输入/期望输出，桌面 Flutter、iOS、Android bindings 全部跑同一组场景。
- **时区测试**：为首批地区选择 IANA zone；覆盖午夜、月末、闰年和 DST 变更（适用地区）。系统本地时区切换后立即重算。
- **性能基准**：代表性 holiday dataset 下 compute p50/p95/p99、内存分配和 timeline 批量生成；目标单次 <1 ms。
- 命令门禁：`cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`cargo test --release`、criterion 基准比较。

### 5.2 Flutter/Dart 测试

- Provider/repository 单元测试：状态重算、取消定时器、整秒对齐、系统时间修改、设置变更、暂停/恢复、JSON schema migration。
- Widget 测试：迷你/标准/展开、全指标、隐藏金额、空设置、校验提示、自定义倒计时 CRUD、超长本地化标签、大字号、窄窗口滚动。
- Integration 测试：首次引导、即时保存、重启恢复、隐藏/显示、托盘命令、快捷键、timerpack 导入/拒绝/导出。
- 命令门禁：`dart format --set-exit-if-changed`、`flutter analyze`、`flutter test`；关键 UI 流程由 integration_test 覆盖。

### 5.3 原生小组件测试

- iOS：TimelineProvider 的 entry 日期、倒计时更新边界、App Group 配置/迁移、隐私金额同步、主 app 未启动时的数据读取；在最低支持 iOS 与当前 iOS 模拟器/真机检查。
- Android：provider 更新、共享偏好、进程重启后恢复、不同 launcher/尺寸、后台刷新限制；最低支持 API 与当前 Android 模拟器/真机检查。
- 验证两端 widget 都通过 UniFFI 调用同一 Rust facade；禁止复制计薪或日历业务规则。
- 薪资组件测试按“最近更新时间”验证，不以系统调度精确每分钟为验收条件。

### 5.4 平台手工验证矩阵

| 领域 | Windows | macOS | iOS | Android |

### 5.5 数据、隐私与安全测试

- 节假日 JSON schema、地区/年份覆盖、来源许可、签名/校验、损坏/过期/缺失/网络失败和手动导入。
- 皮肤包压缩炸弹/路径穿越/超大小/错误 manifest/不支持资源/MIME 伪装；只接受白名单资源，不执行内容。
- 配置导入非法字段、超大文件、旧 schema、缺失字段、未知字段；迁移失败保留原文件并可恢复。
- 网络抓包确认只请求节假日数据，无薪资、出生日期、退休日期、自定义倒计时或配置上传。
- 日志扫描敏感字段；异常信息不得包含月薪或完整用户设置。
- 文件权限和卸载/升级行为验证；导入导出文件由用户显式选择路径。

## 6. 端到端验收场景

1. 月薪 22,000、22 个工作日、9:00–18:00、午休 12:00–13:00：12:00 今日已赚为 375.00；午休期间不变；18:00 达到 1,000.00。
2. 在有效工作时段等待多个整秒，金额严格按 Decimal 规则更新；改变系统时间后下一次结果立即按新时间重算。
3. 周六发薪日顺延至下周一；31 号发薪规则在短月按月末规则处理；月末顺延跨月不重复计次。
4. 周末 + 法定假期 + 周末合并成连续休息段；倒计时落在最后工作日下班时刻。
5. 生命倒计时覆盖 2 月 29 日出生、超过预期寿命；退休倒计时覆盖当天和过期。
6. 新建名为“产品上线”的目标倒计时，验证按秒变化、编辑、删除、重启持久化及到期状态。
7. 迷你指标全开、全关后逐项恢复，排序、缩小窗口、长翻译、大字号及重启后偏好保持。
8. 切换隐藏金额、临时查看、全局快捷键和托盘命令；移动小组件不得泄漏明文金额。
9. 断网启动，核心计时、薪资及内置节假日可用；数据缺失时正确提示并按每周工作日降级。
10. 电脑休眠后跨过午休/下班，唤醒一秒内展示正确状态，不依赖进程期间累加。
11. iOS/Android 主应用关闭时，小组件仍读取上次共享设置并显示；薪资更新时间准确标记。

## 7. 性能、稳定性和发布验收

- 桌面：平均 CPU <1%、内存 <120 MB、冷启动 <2 秒。
- 移动：平均 CPU <2%、应用内存 <80 MB、冷启动 <1.5 秒；小组件独立内存按系统上限及 M0 实测门槛评估。
- 核心 compute <1 ms；使用 release 构建、固定设备和指定代表性节假日数据测量，记录均值和 p95。
- 7 天常驻测试至少覆盖 Windows 与 macOS 各一台；每日采集内存、CPU、刷新/异常日志。
- 100 次显示隐藏/形态切换、100 次皮肤切换、至少 10 次休眠唤醒，确认无窗口丢失、资源泄漏和状态漂移。
- 发布包需版本号、架构、依赖清单、校验和；macOS 签名/公证流程、Windows 安装包及 SmartScreen 风险说明、移动端签名配置均由 CI 或受控构建流程复现。
- 最终 RC 需完成安装、首次启动、升级覆盖、设置迁移、卸载/重装数据行为、无网络运行和回滚演练。

## 8. 缺陷级别与发布门槛

- **P0 阻断**：金额错误/隐私泄漏、核心倒计时错误、崩溃或数据丢失、主要平台无法启动、窗口无法恢复/关闭、签名/安装失败。不得发布。
- **P1 严重**：核心流程无法完成、主要平台关键行为失效、数据更新损坏设置、重要小组件错误。不得发布；若明确缩小发布平台/范围需产品书面决策并更新版本。
- **P2 一般**：非核心视觉或可绕过问题；可带已知问题发布，须有复现、影响和后续版本记录。
- 发布候选必须：P0=0、P1=0；第 13 节所有验收用例通过；性能/长稳门槛通过；平台签名与数据许可材料齐全。
