# 桌面悬浮计时器原型讨论

状态：讨论中  
依据：`../最终确认-可以开始开发.md`（2026-11-04）  
原则：只讨论已冻结功能如何呈现与操作，不借原型重新扩大一期范围。本文中的界面建议都不是冻结决策。

## 讨论范围

- 桌面：Windows / macOS 常驻悬浮窗、迷你/标准/展开三种形态、设置入口与托盘/菜单栏。
- 移动端：iOS / Android 全屏应用、小组件；倒计时类持续显示，薪资类约每分钟更新并标注更新时间。
- 视觉与交互：围绕冻结功能讨论信息层级、设置流程、浮窗形态和跨平台适配。

## 一期冻结边界

- 六类核心数据：生命、上下班、今日与本月薪资、发薪日、下次放假、退休倒计时。
- 薪资仅月薪输入；税前/税后双输入，用户选择显示口径；薪资只在有效工作时段增长。
- 发薪支持每月固定日、每月最后工作日、每月两次；固定双休，不支持大小周或跨零点夜班。
- 首批地区为中国大陆、美国、日本、韩国、中国香港、中国台湾；首批语言为简中、英文、繁中、日文、韩文、西班牙文、德文、法文。
- 桌面悬浮窗支持透明无边框置顶、拖拽、吸边、点击穿透、三种形态和多显示器。
- 两套内置皮肤：简约卡片、深色科技；资源包导入/导出、双击安装及单素材替换属于冻结范围。
- 移动端包含全屏应用与小组件；倒计时类走秒，薪资类每分钟更新并显示“约 X 分钟前更新”。
- 通知、带薪/无薪假、长按预览、菜单栏文字、自动更新属于暂不做或后续项；不在本轮原型中表现为一期承诺。

## 原型讨论方向

原型先覆盖“桌面浮窗 + 移动端全屏页 + 手机小组件”三类主要界面，不预设特定几何造型或视觉方案：

- 桌面迷你态：显示可配置的多项指标，逐项开关和排序；默认包含下班、今日已赚、放假、生命、退休倒计时。
- 桌面标准态：展示用户勾选的多个指标，讨论默认内容、顺序和窗口尺寸。
- 桌面展开态：呈现更多指标、次要信息与工作进度，同时保留拖拽、吸边、置顶和点击穿透等行为。
- 手机全屏：依据移动端使用场景重新组织信息，不直接放大桌面浮窗。
- 手机小组件：分别验证倒计时与薪资信息的呈现密度，薪资更新时间和系统刷新限制必须明确。

## 首轮需要一起定的体验问题

1. 迷你态多项指标同时显示时，窗口高度如何控制？
2. 桌面标准态默认展示哪些指标、顺序如何？
3. 展开态相较标准态应增加哪些次要信息？
4. 移动端首页与桌面浮窗是否共用信息层级，还是只共享数据与皮肤令牌？
5. 移动小组件如何分别呈现倒计时与薪资，如何说明薪资更新时间？
6. 桌面与移动端的设置分组和字段如何保持一致，同时隐藏不适用的平台选项？

## 暂定原型结构

- 桌面主窗口：迷你 / 标准 / 展开三态；迷你态多指标可开关、排序并可全部显示。
- 桌面设置：按冻结分组组织；优先验证“显示内容与顺序”“形态与外观”“位置与行为”“个人信息/作息/薪资”“地区语言与假期”。
- 移动首页：主倒计时焦点、薪资摘要、其他倒计时列表；具体布局待讨论。
- 移动设置：沿用同一设置分组与字段，不照搬桌面窗口行为项；小组件的添加与刷新说明按系统能力呈现。
- 小组件：至少讨论倒计时类与薪资类的密度、更新时间和圆形表达边界。
