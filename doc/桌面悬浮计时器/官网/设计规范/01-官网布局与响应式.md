# 01 官网布局与响应式

[设计规范总览](README.md) · [配色、字体与组件](02-配色字体与组件.md) · [猫猫、截图与素材](03-猫猫截图与素材.md)

## 1. 首屏要传达什么

从个人站「构建」页点击时余，访客进入 `/shiyu/`。首屏先让人认出橘猫贴着电脑桌面上的倒计时窗口，再提供查看各平台状态或下载的入口。薪资是旁边那张较小的浮窗，页面往下才详细解释。

- 品牌写「时余」；导航可以在中文标识旁小字显示「Shiyu」。
- 首屏标题为「桌面上有只猫，陪你看倒计时。」可在逗号处自然换行，手机由实际宽度决定行数。
- 首屏说明为「抬眼就能看到离下班、发薪、放假还有多久。把常看的倒计时合在一起，或拆成小窗摆在桌面上。」
- 首屏图呈现两个完整真实浮窗。奶油黄的「距离下班」为主，坐姿猫贴窗沿。较小的粉桃色「今日已赚」置于右下或下方，蜷睡猫贴其上沿。薪资值使用示例数据。

## 2. 页面结构

| 顺序 | 区块 | 内容与动作 |
| --- | --- | --- |
| 1 | 顶部导航 | 左侧橘猫图标与时余，右侧「功能」「下载」「常见问题」。页面内锚点分别为 `#features`、`#download`、`#faq`，品牌回到页首 |
| 2 | 首屏 | 主标题、说明、主要按钮、条件显示的次入口，以及一张两窗口产品图 |
| 3 | 功能一 | 「想看什么，就放在桌面上」。同一组指标的合并、拆分两张图，用图片标题区分 |
| 4 | 功能二 | 「今日已赚，想看就看」。同一张薪资卡的示例金额与金额遮蔽两种状态，说明整项隐藏和遮蔽金额 |
| 5 | 功能三 | 「手机上，猫猫住在主屏幕」。主屏幕原生小组件实图，标注平台。区块末尾显示支持的指标和「查看各平台状态」 |
| 6 | 下载 | 固定 Windows、macOS、Android、iOS 顺序。各卡片显示独立发布状态、渠道和下载信息 |
| 7 | FAQ | 估算金额、隐私、兼容性、小组件和反馈。每项可展开阅读，问题标题显示完整 |
| 8 | 页脚 | 小号品牌标识、使用说明、隐私说明和已确认的反馈入口 |

浏览顺序与页面阅读顺序一致。导航锚点滚动后为标题保留导航高度加 12px 的空间。下载失败时保留页面其余内容，用户仍能查看功能和 FAQ。

## 3. 桌面布局

- 参考视口为 1440 × 900 CSS px。主内容最大宽度 1184px，两侧居中，视口变窄时边距随档位调整。顶部导航常态高 72px。
- 首屏为左文右图。内容列与图列按约 5∶7 分配，间距 48px。文字列从标题、说明到按钮依次向下，标题与说明间隔 16px，说明与按钮间隔 24px。首屏上下留白为 72px 和 88px。
- 右侧图以约 3∶2 的浅暖纸色画面承托两个浮窗，外框可使用 28px 圆角。主窗置于图的左中部，薪资窗在右下。图的完整边缘保留猫耳、尾巴、标题、时间与窗体四角。
- 三段功能交替排列。浮窗段左图右文，薪资段左文右图，小组件段左图右文。图文间隔 32–48px；每段上下留白 72–88px。两态对照图使用等宽画面，图注统一在下方。
- 下载区下方保留弹性空间给多个架构或商店入口。FAQ 标题和问题左沿对齐全站内容网格，问题列表宽度上限为 800px。页脚使用同一内容网格和细分隔线。

## 4. 响应式规则

以下数值为实现基准，验收时优先保证标题、按钮和截图的完整性。

| 项目 | ≥1200px | 960–1199px | 600–959px | <600px |
| --- | --- | --- | --- | --- |
| 页面横向边距 | ≥32px | 28–32px | 24px | 16–20px |
| 导航 | 72px，品牌与链接同行 | 同左 | ≥64px | ≥60px，品牌与 3 个短链接优先同行，字号放大时可自然换行 |
| 首屏 | 双列，间距 48px | 双列，间距约 32px | 单列，文字在上、画面在下 | 单列，标题、说明、按钮、画面依次向下 |
| 功能段 | 图文双列，段间 72–88px | 双列 | 单列，段间 56–64px | 单列，段间 48–56px |
| 下载卡 | 四列 | 两列 | 两列 | 一列 |
| 对照图 | 两张并列 | 两张并列 | 能读清时并列 | 字号不足时纵向排成两张，不缩到难以辨认 |

手机首屏主按钮占一整行，次入口存在时放下一行或用短链接。390 × 844 视口应能看到标题、主按钮和两张浮窗；360 × 640 的首屏优先露出完整标题、可点击主按钮和主窗图开头，继续向下可看完整的两张图。使用手机专用构图，保证示例薪资窗和主倒计时不会因裁切消失。

桌面、平板和手机使用同一内容。功能段收窄时按「标题与说明 → 对应画面 → 图注」阅读。页脚链接窄屏自然换行。页面在 320px 宽以及浏览器文字放大时无横向滚动，按钮、链接、问答和下载状态可继续访问。

## 5. 下载、问答与链接交互

- 首屏和下载区由同一次公开状态查询更新。唯一明确渠道可显示「下载 Windows 版」「下载 macOS 版」「下载 Android APK」「加入 TestFlight」或对应商店名称。对应平台有多种架构或渠道时，主按钮改为「查看该平台下载」，定位到该卡片。
- 推荐平台未知、接口尚未返回或无可用入口时，主按钮为「查看各平台状态」。次入口只在主按钮直达下载或商店时显示「查看所有平台」。两者指向同一处时留一个按钮。
- 下载区失败用「暂时无法获取下载状态」与「重试」。下架状态用「当前未开放下载」，正文与 FAQ 保持可读。状态框不出现空白按钮、无效直链或虚构版本。
- FAQ 默认折叠，允许同时打开多个问题。建议使用原生 `details/summary`，键盘可展开和收起。问答条目末尾以实际页面或已确认的渠道为准。
- 静态页面预留标题、图、功能说明、平台说明和 FAQ。关闭 JavaScript 时仍能阅读这些内容，并能跳至下载说明。

## 6. 评审检查

- [ ] 在 1440、1024、768、390、360 和 320px 查看页面，核对网格、首屏顺序和无横向溢出。
- [ ] 只看首屏，首次访客能用一句话复述「桌面、猫猫、倒计时」，画面主次与文案一致。
- [ ] Windows、macOS、Android、iOS 都可手动选择。分别验证单渠道、多架构、全准备、失败和下架状态。
- [ ] 用键盘完成导航、下载卡和 FAQ，页面放大后按钮可达。移动图里两张浮窗标题、数字和贴纸完整。
