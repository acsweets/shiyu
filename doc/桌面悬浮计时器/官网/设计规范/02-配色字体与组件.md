# 02 配色、字体与组件

[设计规范总览](README.md) · [官网布局与响应式](01-官网布局与响应式.md) · [猫猫、截图与素材](03-猫猫截图与素材.md)

## 1. 视觉基调

官网延续应用的暖白文具风。页面像暖白纸，标题和按钮像深棕印字，奶油黄和粉桃来自浮窗本身。重点区块可铺一层淡纸色，正文、卡片和页脚保持统一色温。页面以留白、细分隔线和字重分组，猫猫和真实产品图负责营造贴纸感。

## 3. 字体和间距

字体沿用系统无衬线。中文优先使用系统的苹方、微软雅黑或思源黑体，西文和数字用系统 UI 字体。字号使用相对单位换算，保留浏览器字号放大能力。

| 级别 | 桌面字号 / 行高 | 手机字号 / 行高 | 字重 |
| --- | --- | --- | --- |
| 首屏标题 | 50–54px / 1.16–1.22 | 32–36px / 1.2–1.28 | 700 |
| 功能与下载区标题 | 32–36px / 1.25 | 25–28px / 1.3 | 700 |
| 平台卡或 FAQ 小标题 | 19–22px / 1.35 | 18–20px / 1.4 | 700 |
| 介绍正文 | 16–18px / 1.65–1.75 | 16px / 1.65 | 400 |
| 图注、标签与元数据 | 13–14px / 1.5 | 13–14px / 1.5 | 400–600 |
| 按钮和导航 | 15–16px / 1.4 | 14–16px / 1.4 | 600 |

- 间距基准为 4、8、12、16、24、32、48、64、80px。卡片内边距桌面 24px，手机 16–20px；下载卡之间 16–24px。
- 常用圆角为标签圆角、按钮 12px、卡片 16–20px、图框 24–28px。弱阴影可用 `0 10px 28px rgba(57, 37, 26, 0.08)`，主要留给展示图，内容卡片以边界和留白区分。
- 版本、架构和文件大小使用等宽数字特性，SHA-256 使用等宽字体并允许换行。产品截图中的倒计时字体、字重和格式保持应用原样。

## 4. 组件规范

| 组件 | 样式和内容 | 状态 |
| --- | --- | --- |
| 主按钮 | 高度至少 48px，桌面横向内边距 20–24px。浅暖黄底和深棕文字，使用动词起头 | 默认、悬停、按下、键盘焦点。根据发布状态切换文案和链接 |
| 次入口 | 有清楚描边的按钮，或带下划线的短文字链接 | 与主按钮同目标时只展示一个；键盘焦点可见 |
| 导航链接 | 使用深棕字和清晰点击区域。键盘焦点有外环 | 悬停和当前区块可加下划线或其他明确标记 |
| 平台卡 | 上方平台名和状态，中间版本、系统、架构与文件大小，下方各渠道动作。卡内支持多包并列或纵向排列 | 准备中展示说明；可下载才提供对应链接；多架构明确区分下载按钮 |
| 安装说明和校验和 | 直链卡片在主要动作下提供「查看安装说明和校验和」。展开后可选取完整 SHA-256，长值自然换行 | 支持键盘展开。折叠状态也能快速找到安装入口 |
| FAQ | 问题一行或自然折行，右侧箭头提示展开状态，答案下方有足够留白 | 点击问题整行可切换，读屏可获取展开状态 |
| 加载与错误 | 加载时使用稳定卡片高度和短提示。失败在下载区显示错误说明与重试 | 状态更新后移除过期链接。重试不带用户离开页面 |

## 5. 可访问性和动效

- 以 WCAG 2.2 AA 的对比度要求校验最终实现。设计色值已抽查，主文字与页面底色约为 14.11∶1，正文约 9.08∶1，主按钮文字约 9.05∶1，按下状态约 6.89∶1，操作描边对暖纸约 3.79∶1。语义色文字的对比度均超过 4.5∶1。页面实现后复测叠图、悬停、焦点和实际背景。[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [W3C 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 移动端可操作区域以至少 44 × 44 CSS px 为本项目设计目标。按钮焦点环建议 2px 实线加 2px 间隙，检查在白、暖白和按钮底色上均可见。[W3C 点击目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 页面以静态画面为基准。按钮可使用约 120–180ms 的底色过渡。支持减少动态效果设置时，去掉非必要位移和滚动动画；素材与信息在静态状态下完整可读。

## 6. 评审检查

- [ ] 白纸、暖纸和应用截图有明确层次，首屏未使用大面积高饱和色。
- [ ] 检查主按钮、次入口、链接、状态标签及键盘焦点，长平台名和校验和可完整阅读。
- [ ] 逐一切换发布状态，准备中没有无效下载按钮，错误能重试，多架构能明确选择。
- [ ] 实际页面完成对比度、触控、键盘和减少动态效果验证。
