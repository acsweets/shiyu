# 桌面悬浮计时器 PRD

版本 v1.0 · 日期 2026-11-04 · 状态：待技术评审 · 适用平台：Windows / macOS

阅读指引：第 1 至 13 章为基础需求与初版技术方案；第 14 至 18 章为后续增补，凡与前文冲突，以增补章节为准，前文相应条款已就地标注；第 19 章给出全部待确认问题的定论；第 20 章补全技术方案并给出设置项最终版；第 21 章为范围、追溯与总里程碑。开发实施以第 19 至 21 章为准。

## 1. 产品概述

### 1.1 一句话定义

一个常驻桌面的悬浮小窗，实时显示：生命剩余时间、距离下班、今日与本月已赚薪资、距离发薪日、距离下次放假、距离退休。

### 1.2 目标

- 在不打扰工作的前提下，用一块置顶悬浮窗提供“时间 + 薪资”的即时感知。
- 所有计算以系统时间为准，休眠、唤醒、改时间后不漂移。
- 全部数据本地存储，薪资等敏感信息不上传。

### 1.3 范围

- v1.0：Windows 10+ 与 macOS 12+ 桌面端，两端悬浮窗外观与行为保持一致。
- 暂不包含：手机端（已确定为后续阶段，含手机桌面小组件，见第 18 章）、云同步、账号体系；多地区与多语言已纳入范围，详见第 17 章。
- 核心计算模块需与 UI 解耦，便于后续复用到手机端。

### 1.4 已确认的产品决策

1. 薪资只在工作时间内增长，午休与下班后不增长。
2. 发薪日遇休息日时默认顺延到下一个工作日（可按地区或用户选择改为提前或不调整，见 17.4）。
3. 退休日期由用户直接填写，不做自动推算。
4. 以桌面一致的悬浮提示窗作为主要形态。

## 2. 用户与场景

- 目标用户：上班族，工作时电脑常开。
- 场景 A：上班时窗口停在屏幕角落，扫一眼看到“今日已赚 ¥xxx.xx”和“距离下班 02:14:33”。
- 场景 B：开会共享屏幕前，一键隐藏窗口或隐藏金额。
- 场景 C：每月初设置一次，之后基本无需操作。

## 3. 术语与计算口径

所有时间均使用系统本地时区。金额内部以整数“分”的高精度小数计算，显示时向下截断（避免显示虚高）。

| 术语 | 定义 |
| --- | --- |
| 工作日 | 由每周工作日设置（默认值由所选地区提供，见 17.3）决定，加上调休补班日，减去法定节假日 |
| 每日有效工作秒数 | (下班时间 − 上班时间) − 午休时长，换算为秒 |
| 当月应出勤天数 | 当月自然月内的工作日个数 |
| 每秒薪资 | 当月月薪 ÷ 当月应出勤天数 ÷ 每日有效工作秒数 |
| 今日已工作秒数 | 今日已进入有效工作时段的秒数，午休段不计 |
| 今日已赚 | 每秒薪资 × 今日已工作秒数；非工作日为 0 |
| 本月已赚 | 本月已结束工作日的日薪总和 + 今日已赚；日薪 = 每秒薪资 × 每日有效工作秒数 |

示例：月薪 22000，当月 22 个工作日，作息 9:00–18:00、午休 12:00–13:00（有效 8 小时）。日薪 1000 元；12:00 时已工作 3 小时，今日已赚 375.00 元；13:00 午休结束前不再增长。

## 4. 功能需求

优先级：P0 为 v1.0 必须，P1 为 v1.0 争取，P2 为后续版本。

### 4.1 F1 生命倒计时（P0）

- 输入：出生日期（必填）、出生时刻（可选，默认 00:00）、预期寿命（年，支持一位小数，默认 100）。
- 死亡时刻 = 出生时刻 + 预期寿命（按日历加年；2 月 29 日出生者在非闰年按 2 月 28 日处理）。
- 显示：剩余秒数（千分位格式，每秒刷新）。点击可切换为：剩余天数、剩余周数、剩余“周末”个数、“年 天 时 分 秒”。
- 超过预期寿命时显示“已超出预期，请调整设定”，不显示负数。

### 4.2 F2 上下班（P0）

- 设置项：上班时间、下班时间、午休开始、午休结束（午休可关闭）。v1 不支持跨零点夜班（下班时间必须晚于上班时间，保存时校验）。
- 状态机与显示文案：

| 状态 | 判定 | 主显示 |
| --- | --- | --- |
| 休息日 | 今日非工作日 | 距离下个工作日上班 X 天 hh:mm:ss |
| 未上班 | 工作日，当前早于上班时间 | 距离上班 hh:mm:ss |
| 上班中 | 处于有效工作时段 | 距离下班 hh:mm:ss（下班时间减当前时间，墙钟时间，含午休） |
| 午休中 | 处于午休时段 | 距离午休结束 hh:mm:ss；薪资暂停 |
| 已下班 | 当前晚于下班时间 | 距离明天（或下个工作日）上班 |

- 可选显示今日工作进度条（已工作秒数 ÷ 每日有效秒数）。

### 4.3 F3 实时薪资（P0）

- 设置项：税前月薪（必填）、税后月薪（可选）、币种（ISO 4217 代码，默认由地区提供，见 17.5）、显示口径（税前 / 税后，默认税前；未填税后时该选项置灰）。
- 显示：今日已赚、本月已赚（精度默认 0.01 元，可选 2 到 4 位小数）。
- 仅有效工作时段内增长；午休、下班后、休息日保持不变。
- 每月使用该月自身的应出勤天数重新计算每秒薪资，月薪额度不变，因此工作日越少的月份每秒薪资越高。
- 隐私：支持“隐藏金额”开关，开启后显示为 \*\*\*\*，点击眼睛图标临时查看；全局快捷键可一键切换。
- 带薪假 / 无薪假（P1）：用户可在自定义假期中标记。带薪假视为当日已赚满日薪；无薪假从当月应出勤天数中剔除，当日不计薪。

### 4.4 F4 发薪日倒计时（P0，规则扩展见 17.4）

- 设置项：每月几号发薪（1–31）。
- 实际发薪日规则：若设置的日期大于当月天数，取当月最后一天；若实际日期为周末或法定节假日，顺延到下一个工作日（顺延可跨月，例如月末遇长假）。
- 目标时刻：实际发薪日当天 00:00。显示“距离发薪 X 天 hh:mm:ss”。发薪日当天显示“今天发薪”，过了当天自动切换到下个月。
- 若本月实际发薪日因顺延被推到下月，仍以该实际日期为准，不重复计算。

### 4.5 F5 下次放假倒计时（P0）

- 数据来源：法定节假日 + 用户自定义假期（年假、调休、公司假，可设起止日期与名称）。
- 设置项：“周末算放假”开关（默认开）。
- 目标时刻：下一段连续休息日开始前，最后一个工作日的下班时间。显示“距离放假（国庆节）X 天 hh:mm:ss”。
- 当前正处于休息日时，显示“放假中，距离结束 X 天”，并在其后展示下一次放假信息。
- 连续休息段需合并（例如周末 + 法定假 + 周末视为一次长假）。

### 4.6 F6 退休倒计时（P0）

- 设置项：退休日期（用户直接填写）。
- 显示：剩余总天数（主），点击切换为“年 月 天”或“天 hh:mm:ss”；可选显示剩余工作日数（扣除周末与节假日）。
- 已到或已过退休日期显示“已退休”，不显示负数。

### 4.7 F7 悬浮窗（P0，详见第 5 章）

### 4.8 F8 设置页（P0）

- 分组：个人信息、作息与薪资、日期与假期、悬浮窗外观、通用。
- 所有设置修改后立即生效并自动保存，无需“保存”按钮；非法输入就地提示并保留上次合法值。
- 首次启动进入 3 步引导：个人信息 → 作息与薪资 → 悬浮窗预览。
- 支持设置导出与导入（JSON 文件，本地）。

### 4.9 F9 托盘与菜单栏（P0）

- Windows 为系统托盘图标，macOS 为菜单栏图标。
- 菜单项：显示/隐藏悬浮窗、隐藏金额、打开设置、暂停计时显示、检查节假日数据更新、退出。
- 可选（P1）：菜单栏文字显示“今日已赚 ¥xxx.xx”或“距下班 hh:mm”。

### 4.10 F10 通知（P1）

- 下班前 N 分钟提醒、发薪日当天提醒、放假前一天提醒；使用系统原生通知，均可单独开关。

## 5. 悬浮窗规格

### 5.1 窗口行为

| 项目 | 要求 |
| --- | --- |
| 外观 | 无边框、背景透明、圆角卡片，两端视觉一致 |
| 置顶 | 默认置顶；可在设置中关闭 |
| 任务栏 / Dock | 默认不显示窗口图标，仅托盘或菜单栏入口 |
| 拖拽 | 按住卡片任意空白处拖动；位置按显示器记忆，重启后恢复；若记忆的显示器已不存在，回到主屏右上角 |
| 吸边 | 靠近屏幕边缘 12px 内自动吸附（可关闭） |
| 点击穿透 | “锁定”模式下鼠标事件穿透，窗口只显示不可点；从托盘取消锁定 |
| 多显示器 | 可在任意屏幕；跨 DPI 屏幕移动时清晰缩放 |
| 全屏应用 | 默认不遮挡全屏应用；提供“在全屏应用上方显示”选项（macOS 需覆盖全屏 Space） |
| 全局快捷键 | 显示/隐藏窗口，默认 Ctrl/Cmd + Shift + T，可自定义；另设“隐藏金额”快捷键 |
| 单实例 | 重复启动时唤起已有实例 |
| 自启动 | 可选开机自启，默认关闭 |

### 5.2 显示形态

- 迷你：单行，仅显示用户选定的一个指标（如“距下班 02:14:33”）。
- 标准：卡片，显示用户勾选的多个指标，默认顺序为：上下班、今日已赚、本月已赚、发薪日、放假、退休、生命。
- 展开：在标准基础上显示进度条和次要信息。
- 每个指标可单独显示/隐藏、调整顺序；双击卡片在迷你与标准间切换。

### 5.3 外观设置

- 主题：浅色 / 深色 / 跟随系统；透明度 30%–100%；字号三档；强调色可选。
- 数字使用等宽（tabular）数字，避免每秒跳动时宽度抖动。

### 5.4 刷新策略

- 每秒刷新一次，对齐系统整秒边界。
- 悬浮窗隐藏或系统锁屏时暂停界面刷新，恢复可见时立即重算。
- 禁止“每秒 +1”累加；每次刷新均用目标时刻与当前系统时间重新计算。
- 监听系统休眠唤醒、系统时间被修改、时区变化，触发立即重算。
- 日期跨零点时自动重新计算工作日、应出勤天数与每秒薪资。

## 6. 节假日数据

- 范围：支持多个国家与地区，数据结构、来源与更新机制见 17.2。
- 数据源：优先采用社区维护的开源节假日数据（如 holiday-cn，按年份 JSON），安装包内置当年及次年数据。
- 更新：启动后每日最多联网检查一次；失败时静默使用本地缓存，不弹错；菜单支持手动检查与手动导入 JSON。
- 数据缺失：若某年节假日尚未发布，按“周一至周五为工作日”降级，并在设置页与悬浮窗标注“节假日数据未更新”。
- 用户可对任意日期手动覆盖为“工作日”或“休息日”，覆盖优先级高于内置数据。
- 所有联网请求只下载节假日数据，不得携带任何用户设置。

| currencySymbol | 字符串 | 默认 ¥ |
| moneyPrecision | 整数 | 2–4，默认 2 |
| payDay | 整数 | 1–31 |
| weekendCountsAsHoliday | 布尔 | 默认 true |
| customHolidays | 列表 | 名称、起止日期、类型（带薪 / 无薪 / 普通） |

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 精度 | 计时误差不超过 1 秒；金额计算使用十进制高精度，不使用二进制浮点累加 |
| 性能 | 常驻 CPU 平均占用低于 1%；内存低于 150MB（理想低于 100MB）；窗口隐藏时无持续高频计算 |
| 启动 | 冷启动到悬浮窗可见不超过 2 秒 |
| 稳定性 | 连续运行 7 天无明显内存增长；崩溃后下次启动恢复到上次设置 |
| 兼容 | Windows 10 / 11（含 125%、150%、200% 缩放）；macOS 12 及以上（Intel 与 Apple Silicon） |
| 安全与隐私 | 无账号、无埋点；联网仅限节假日数据；macOS 需签名与公证，Windows 建议代码签名 |
| 可访问性 | 支持高对比主题；字号三档 |
| 可测试性 | 计算核心为无副作用的纯函数：输入（设置、当前时间、节假日数据），输出各指标；时间必须可注入 |

## 9. 边界情况

1. 月薪或作息未填写：对应指标显示“未设置”，不报错，点击跳转设置。
2. 当月无工作日（极端情况）：每秒薪资视为 0，今日与本月已赚为 0。
3. 在上班时间中途修改作息或月薪：今日已赚按新设置重算，不保留旧值。
4. 电脑休眠跨过下班时间：唤醒后立即显示“已下班”，今日已赚为满额。
5. 发薪日顺延跨月、发薪日设置为 31：按 4.4 规则处理。
6. 调休补班的周末：视为工作日，计入应出勤天数并实时计薪。
7. 夏令时：v1 以大陆时区为主，使用系统本地时区计算，不单独处理夏令时。
8. 悬浮窗位置落在已断开的显示器：回到主屏。
9. 系统时间被手动改到过去或未来：立即按新时间重算，不做防篡改。

## 12. 待确认事项（已全部在第 19 章定论）

1. “下次放假”默认包含周末是否合适，或默认仅算法定假期与自定义假期？
2. 发薪日倒计时的目标时刻采用当天 00:00，还是当天上班时间？
3. 是否需要“大小周”“单休”等自定义工作日规则（因各地区周末不同，已定为 P0，见 17.3；大小周的轮换规则仍为 P1）？
4. v1 之后做手机端：已确定，手机桌面小组件是明确目标，见第 18 章。
5. 是否有分发渠道限制（如 Mac App Store），会影响透明窗口等私有 API 的使用。

## 13. 技术方案

### 13.1 选型结论

采用 Flutter Desktop 一套代码覆盖 Windows 与 macOS。理由：团队技术栈为 Flutter；自绘渲染保证两端悬浮窗外观一致；无需使用透明窗口私有 API，不影响上架 Mac App Store；核心计算库采用 Rust，通过绑定供 Flutter 应用与手机小组件共用，详见第 18 章。

### 13.2 依赖选型（核心库相关项以第 18 章为准）

| 用途 | 方案 |
| --- | --- |
| 窗口管理（透明、置顶、穿透、拖拽、跳过任务栏） | window\_manager |
| 托盘与菜单栏 | tray\_manager |
| 全局快捷键 | hotkey\_manager |
| 开机自启 | launch\_at\_startup |
| 多显示器信息 | screen\_retriever |
| 系统通知（P1） | local\_notifier |
| 自动更新 | auto\_updater（Windows 使用 WinSparkle，macOS 使用 Sparkle） |
| 金额计算 | decimal |
| 时间注入（便于测试） | clock |
| 状态管理 | Riverpod |
| 本地存储 | JSON 文件 + path\_provider |
| 节假日更新 | http 或 dio，内置 JSON 放入 assets |

### 13.3 工程结构（以 18.2 为准）

工程拆为两个包：packages/core 为纯 Dart，不依赖 Flutter，负责全部业务计算；app 为 Flutter 应用，负责窗口、状态与界面。

```
countdown/
├─ packages/core/
│   ├─ models/      Settings、DayType、HolidayData、Snapshot
│   ├─ calendar/    工作日判定、应出勤天数、发薪日顺延、下次放假
│   ├─ salary/      每秒薪资、今日已赚、本月已赚
│   ├─ life/        生命倒计时
│   └─ compute.dart 统一入口
└─ app/
    ├─ platform/    窗口、托盘、热键、原生通道
    ├─ state/       Riverpod providers
    └─ ui/          悬浮窗、设置页
```

### 13.4 核心接口约定（以 18.3 为准）

- 统一入口：Snapshot compute(Settings settings, DateTime now, HolidayData holidays)，为无副作用的纯函数，不得在内部读取系统时间。
- Snapshot 包含：workState（休息日、未上班、上班中、午休中、已下班）、距离下一状态切换的 Duration、todayEarned、monthEarned、perSecondSalary、nextPayDate 与距离、nextHoliday（名称、目标时刻）、retireRemaining、lifeRemainingSeconds。
- 金额字段使用 Decimal，仅在 UI 层按 moneyPrecision 向下截断后格式化。
- 日期运算使用本地日期，不手写时区偏移；跨月、跨年、闰年的边界用例必须有单元测试。
- PRD 第 10 章验收用例 AC-1 至 AC-8 与 AC-12 直接转为 packages/core 的单元测试，作为合入门禁。

### 13.5 关键实现要求

**计时**

- 禁止用 Timer 累加；每次 tick 均用当前系统时间调用 compute 重算。
- tick 对齐整秒：下一次延迟 = 1000 减去当前毫秒数。
- 检测到两次 tick 间隔明显偏大（休眠唤醒、改系统时间）时立即强制刷新。
- 窗口隐藏或锁屏时暂停 UI 刷新，可见时立即重算。

**悬浮窗**

- 使用 window\_manager 设置无边框、透明背景、置顶、跳过任务栏、鼠标事件穿透。
- 阴影与圆角由 Flutter 自绘，不依赖系统窗口阴影，保证两端一致。
- 迷你、标准、展开三种形态通过调整窗口尺寸切换，需避免切换闪烁。
- 每秒仅重绘变化区域，使用 RepaintBoundary 隔离；数字使用等宽字体直接替换，不做滚动动画。

**macOS 专项**

- 修改 MainFlutterWindow.swift：isOpaque 设为 false，backgroundColor 设为 clear，关闭系统阴影。
- 在 Info.plist 设置 LSUIElement，应用不出现在 Dock。
- 全屏应用上方显示：编写少量 Swift，设置窗口层级与 collectionBehavior（canJoinAllSpaces、fullScreenAuxiliary），通过 MethodChannel 暴露给 Dart。
- 上架 Mac App Store 需开启沙盒，并开启 network.client 权限用于下载节假日数据；需签名与公证。

**Windows 专项**

- 重点验证透明无边框窗口在 125%、150%、200% 缩放及多显示器间拖动时的表现，以及首次显示是否闪黑。
- 打包采用 MSIX 或 Inno Setup，并做代码签名，避免 SmartScreen 警告。

### 13.6 M0 原型验证清单（约 1 周）

仅实现悬浮窗外壳，数据写死，全部通过后再进入 M1：

1. Windows 与 macOS 均实现透明、无边框、圆角、自绘阴影，且视觉一致。
2. 置顶、拖拽、位置记忆在多显示器与不同 DPI 下正常。
3. 点击穿透可开启，也可从托盘取消。
4. macOS 在全屏应用上方显示，且不抢焦点。
5. 隐藏 Dock 或任务栏图标，仅保留托盘入口。
6. 全局快捷键可呼出与隐藏窗口。
7. 连续运行 24 小时，实测 CPU 与内存，若超过 PRD 第 8 章指标则评估是否调整指标。
8. 休眠唤醒后 1 秒内数值恢复正确。

### 13.7 对前文条款的修订

- 第 12 章第 4 项（手机端）：倾向于做，核心库已按纯 Dart 设计，手机桌面小组件仍需原生开发。

## 14. 显示模式与长按预览交互（新增，补充并优先于 4.9、5.1 的对应条款）

### 14.1 显示模式

| 模式 | 说明 |
| --- | --- |
| 常驻模式 | 悬浮窗持续显示在桌面，行为遵循第 5 章；托盘或菜单栏图标左键单击切换窗口显示与隐藏 |
| 隐藏模式 | 悬浮窗平时不显示，仅保留托盘（Windows）或菜单栏（macOS）图标；通过 14.2 的长按预览查看信息 |

- 模式可在设置页与托盘菜单中切换，切换后立即生效并记忆，默认为常驻模式。
- 两种模式共用同一套内容、皮肤与外观设置。

### 14.2 长按预览交互（隐藏模式，P0）

**触发入口**：Windows 为系统托盘图标，macOS 为菜单栏图标。

**基本流程**：左键按下图标，立即显示预览窗；松开左键，预览窗立即隐藏（默认 150ms 淡出，可在设置中关闭动画）。

**短按与长按**：为避免普通点击造成闪现，按以下规则区分，长按阈值默认 250ms，可在 0 到 1000ms 范围内调整。

| 操作 | 结果 |
| --- | --- |
| 按住时间不小于阈值后松开 | 预览窗隐藏（长按预览） |
| 按住时间小于阈值后松开 | 预览窗保持显示，进入固定显示状态，不发生隐藏再显示的闪烁 |
| 固定显示状态下再次点击图标、按 Esc、点击窗口外区域 | 预览窗隐藏 |
| 右键点击图标 | 打开托盘菜单（原 F9 菜单项不变） |

**预览窗位置**

- 默认锚定在图标附近：macOS 位于菜单栏图标下方并水平居中；Windows 按任务栏所在边（下、上、左、右）自适应，显示在图标旁。
- 超出屏幕边缘时自动平移，保证完整可见；多显示器时出现在图标所在显示器。
- 提供设置项「在上次常驻位置显示」，默认关闭。

**预览窗行为**

- 长按预览期间窗口为只读，不抢占焦点，不接收鼠标事件。
- 固定显示状态下可点击切换指标，但仍不抢占其他应用焦点。
- 预览窗与常驻窗使用同一套渲染，按下到可见的延迟不超过 100ms，因此窗口需预创建并保持在后台，不在每次按下时重新创建。

**异常保护（必须实现）**

- 按下期间由平台层监听鼠标左键的全局状态：Windows 轮询按键状态，macOS 使用全局鼠标事件监听。一旦检测到左键已松开，立即隐藏，避免用户把鼠标拖出图标后松开，导致窗口一直不消失。
- 屏幕锁定、系统弹窗打断、应用失去鼠标捕获时，立即隐藏。
- 兜底：长按预览状态持续超过 30 秒强制隐藏。

**备选触发：快捷键**

- 全局快捷键支持两种行为：切换显示（默认）与按住显示、松开隐藏，可在设置中选择。
- 用于图标被系统折叠或隐藏的场景（见下方平台限制）。

**菜单栏文字（P1）**：隐藏模式下可选在图标旁显示一个用户指定的指标（如距离下班 02:14:33），使不展开窗口也能获得关键信息，每秒刷新。

### 14.3 平台限制与应对

- Windows 11：托盘图标默认可能被折叠进溢出区。首次启动引导用户将图标固定到任务栏，并在设置页提供引导说明。
- macOS：菜单栏图标过多或刘海屏遮挡时，图标可能被系统隐藏。引导用户调整，并建议同时开启快捷键作为兜底。
- 托盘图标的鼠标按下与松开事件，Flutter 现有托盘插件支持程度在各平台不一致，macOS 需要在原生层自定义状态栏按钮的事件处理。此项纳入 M0 原型验证，见 14.5。

## 15. 皮肤系统（新增）

### 15.1 目标与范围

- v1：内置不少于 3 套皮肤（建议：简约卡片、极简单行、深色科技风），用户可在设置页实时预览并切换。
- 支持资源包导入：用户可导入整体风格包，也可只替换个别图片素材，详见第 16 章；L3 自由布局与 L4 动画仍为后续版本。

### 15.2 架构原则

1. **数据与表现分离**：界面只消费核心库输出的 Snapshot，不包含任何业务计算，皮肤不能改变计算结果。
2. **皮肤是数据，不是代码**：Flutter 发布版为提前编译，不能动态加载 Dart 代码，且执行第三方代码有安全风险，因此皮肤采用声明式描述（配置文件加资源文件）。
3. **槽位机制**：每个指标是一个槽位，皮肤决定显示哪些槽位、位置、样式。
4. **内置皮肤走同一套机制**：内置皮肤也通过同样的令牌与模板加载，禁止硬编码，保证后期第三方皮肤与内置皮肤能力一致。

槽位清单：lifeRemaining、workStatus、todayEarned、monthEarned、payday、nextHoliday、retire、progress。

### 15.3 皮肤能力分层

| 层级 | 能力 | 版本 |
| --- | --- | --- |
| L1 设计令牌 | 配色（浅色与深色各一套）、字体、字号、圆角、间距、阴影、边框、背景（纯色、渐变、图片） | v1 |
| L2 布局模板 | 从内置模板中选择，如单行、卡片、网格；模板决定迷你、标准、展开三种形态的窗口尺寸与槽位排布 | v1 |
| L3 自由布局 | 皮肤用声明式配置自定义每个槽位的位置、大小与样式 | P2 |
| L4 动画 | 支持 Lottie 或 Rive 动画资源作为装饰，不参与数据 | P2 |

皮肤明确不支持：自定义业务逻辑、网络请求、读取本地文件、执行脚本。

### 15.4 皮肤包结构（以 16.4 为准）

```
skin-xxx/
├─ manifest.json   id、名称、作者、版本、最低应用版本、预览图
├─ tokens.json     配色、字体、圆角、间距、阴影
├─ layout.json     使用的模板、各形态的窗口尺寸与槽位排布
└─ assets/         图片、字体、动画资源
```

### 15.5 切换与管理

- 设置页提供皮肤列表、缩略预览，选中后立即应用，无需重启。
- 皮肤缺失、损坏或版本不兼容时，自动回退到默认皮肤，并提示用户。
- 切换皮肤不改变用户已勾选的显示项；皮肤不支持的槽位自动忽略。
- 皮肤同时作用于常驻窗口与隐藏模式下的预览窗。
- 皮肤选择写入设置项 skinId，并在 window 对象中保存各皮肤的独立参数（如透明度），切换回来时恢复。

### 15.6 皮肤包导入（已提前至 v1，详见第 16 章）

- 支持从本地目录或 zip 文件导入，导入前校验 manifest 完整性、版本兼容性。
- 限制：单个皮肤包不超过 20MB；资源文件类型白名单（图片、字体、Lottie 或 Rive 文件、JSON）；不执行任何脚本。
- 导入失败给出明确原因，且不影响当前使用的皮肤。

### 15.7 工程要求

- app/ui 下定义统一的皮肤接口：输入为 Snapshot 与当前皮肤定义，输出为可渲染的窗口内容及各形态所需窗口尺寸。
- 窗口尺寸由皮肤的布局模板提供，皮肤切换或形态切换时，窗口尺寸联动调整，避免闪烁。
- 皮肤定义的解析与校验放在独立模块，并有单元测试覆盖：缺字段、非法颜色值、尺寸越界、资源缺失。
- 数字显示统一使用等宽数字，避免每秒跳动时宽度抖动；皮肤自带字体需包含该特性，否则回退到系统等宽数字。

### 15.8 验收标准（新增）

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-20 | 在设置页切换皮肤 | 常驻窗与预览窗即时更换，无需重启 |
| AC-21 | 皮肤配置文件损坏 | 自动回退默认皮肤并提示，应用不崩溃 |
| AC-22 | 切换形态（迷你、标准、展开） | 窗口尺寸按所选皮肤的模板变化，无闪烁 |
| AC-23 | 皮肤不支持的槽位被用户勾选 | 该槽位被忽略，其他显示正常 |
| AC-24 | 新增一套内置皮肤 | 仅新增令牌与布局配置即可完成，无需改动业务与窗口代码 |

### 15.9 里程碑调整

- M1：核心计算库（不变）。
- M2：悬浮窗、托盘或菜单栏、设置页，同时完成皮肤接口、L1 设计令牌与 L2 三个布局模板，以及隐藏模式与长按预览。
- M3：节假日数据、通知、自启动、导入导出（不变）。
- M5（P2，后续版本）：L3 自由布局、L4 动画（资源包导入已提前，见 16.9）。

## 16. 资源包系统（新增，补充并优先于 15.1、15.4、15.6、15.9 的对应条款）

### 16.1 目标与优先级

- 用户无需改代码，即可导入整体风格包一次换掉整套外观，也可只替换个别图片素材，其余保持当前皮肤不变。
- 资源包只包含配置与素材，不包含可执行代码，沿用 15.2 的原则。
- 优先级：风格包导入、素材包导入、设置页单个素材替换均为 P0，纳入 v1；导出为资源包为 P1；L3 自由布局与 L4 动画仍为 P2。

### 16.2 两类资源包与一个轻量入口

| 类型 | 用途 | 内容 | 导入后效果 |
| --- | --- | --- | --- |
| 风格包 | 整体换风格 | manifest、tokens、layout（引用内置布局模板）、assets | 作为新皮肤出现在皮肤列表，可随时切换 |
| 素材包 | 批量替换图片 | manifest 与若干按槽位命名的图片文件 | 覆盖目标皮肤的对应素材槽位，可单独卸载 |
| 单个替换（无需打包） | 个别图片 | 用户在设置页选择一张本地图片 | 立即替换对应槽位，可一键恢复默认 |

### 16.3 素材槽位

每套皮肤声明自己开放哪些素材槽位，包括槽位 ID、类型、建议尺寸、适配方式。内置皮肤的通用槽位如下，具体清单以各皮肤声明为准。

| 槽位 ID | 含义 | 格式 | 建议规格 |
| --- | --- | --- | --- |
| bg.window | 窗口背景图 | PNG、JPG、WebP | 按各形态窗口尺寸的 2 倍图 |
| icon.work | 上下班图标 | SVG、PNG | 64×64 的 2 倍图 |
| icon.money | 薪资图标 | SVG、PNG | 同上 |
| icon.payday | 发薪日图标 | SVG、PNG | 同上 |
| icon.holiday | 放假图标 | SVG、PNG | 同上 |
| icon.retire | 退休图标 | SVG、PNG | 同上 |
| icon.life | 生命倒计时图标 | SVG、PNG | 同上 |
| progress.track、progress.fill | 进度条轨道与填充 | PNG、SVG | 高度 8–24px，支持九宫格拉伸 |
| decor.corner | 角落装饰图（可选） | PNG、WebP | 不超过 256×256 |
| tray.icon | 托盘或菜单栏图标 | PNG | 不小于 128×128，见 16.8 |
| font.digit | 数字字体（v1 不开放，P2） | TTF、OTF | 必须包含等宽数字 |

- 每个槽位可提供深色版本，文件名加 .dark 后缀（如 bg.window.dark.png）；缺失时深浅色共用同一张。
- 颜色、字号、圆角等非图片样式属于风格包的 tokens，不属于素材槽位；用户的强调色等简单选项仍在设置页调整。

### 16.4 资源包结构与 manifest

资源包为 zip 压缩包，扩展名暂定 .cdpack（占位名，待确认）。

```
my-style.cdpack
├─ manifest.json
├─ tokens.json     仅风格包
├─ layout.json     仅风格包
└─ assets/
    ├─ bg.window.png
    ├─ icon.work.svg
    └─ ...
```

| manifest 字段 | 说明 |
| --- | --- |
| packType | style 或 asset |
| id | 全局唯一标识，建议反向域名格式，同 id 高版本视为更新 |
| name、author、version、license | 名称、作者、语义化版本、授权说明 |
| minAppVersion | 要求的最低应用版本，低于时拒绝导入并提示升级 |
| targetSkin | 仅素材包使用，指定适用的皮肤 id；为空表示对所有皮肤的同名槽位生效 |
| preview | 预览图文件名 |
| assets | 槽位 ID 到文件路径的映射 |

### 16.5 导入、预览与卸载

1. 入口：设置页「资源包」的导入按钮，或把文件拖入设置页；双击 .cdpack 文件打开（P1）。
2. 校验：按 16.7 依次检查，任一项不通过即终止，并给出明确原因。
3. 预览：安装前展示预览图、名称、作者、版本、大小、将影响的槽位；风格包支持「试用」，临时应用，取消后恢复原外观。
4. 安装：解压到应用数据目录下的独立文件夹（风格包进 skins，素材包进 overrides），绝不覆盖内置资源。
5. 卸载：资源包列表中可单独卸载；卸载后依赖它的槽位自动回退，若当前正在使用该风格包，则切回默认皮肤。
6. 导出（P1）：可把当前的局部替换导出为素材包，或把当前外观导出为风格包，便于分享。

### 16.6 素材解析与局部替换规则

- 同一槽位的优先级从高到低：用户在设置页的单个替换、素材包覆盖、当前皮肤自带素材、内置默认素材。
- 替换记录按「皮肤 + 槽位」保存：切换到其他皮肤时不生效，切回后恢复；素材包的 targetSkin 为空时，对所有皮肤的同名槽位生效。
- 每个槽位提供「恢复默认」，设置页提供「全部恢复默认」。
- 图片尺寸或比例与槽位不符时，按槽位声明的适配方式处理：裁剪填充、完整显示留边、九宫格拉伸；设置页显示建议尺寸。
- 资源缺失、解码失败时，该槽位回退到下一优先级的素材，不影响其他槽位，应用不崩溃。

### 16.7 安全与限制

| 项目 | 规则 |
| --- | --- |
| 可执行内容 | 禁止脚本、可执行文件、HTML；资源包无法读取设置项，也无法联网 |
| 文件类型白名单 | png、jpg、webp、svg、json（字体槽位开放后再加入 ttf、otf）；按文件头校验真实类型，扩展名与内容不符则拒绝 |
| SVG | 仅允许基础图形与样式，导入时清洗；禁止脚本、外部引用与 foreignObject |
| 体积 | 单包不超过 20MB；单图不超过 5MB；单图边长不超过 4096px；文件数不超过 200；解压后总量不超过 60MB（防压缩炸弹） |
| 路径 | 拒绝绝对路径、上级目录路径与符号链接，防止解压时写出到目标目录之外 |
| 字体与图片版权 | 导入时提示由用户自行确认授权，应用不审核内容；显示来源作者 |
| 动画（Lottie、Rive） | v1 不支持，属 L4 |

### 16.8 工程要求

- 新增素材仓库层：按 16.6 的优先级合成并解析槽位到图片；界面代码不直接读取文件。
- 导入、替换、恢复后立即刷新，无需重启；切换时清理旧缓存，避免内存增长。
- 大图按窗口实际显示尺寸降采样加载，控制常驻内存，并纳入 M0 与 M2 的内存实测。
- 托盘图标：Windows 需要多尺寸图标（16、20、24、32、48），macOS 需要单色带透明通道的模板图像以适配深浅菜单栏。用户只提供一张高分辨率 PNG 时，应用自动生成各尺寸；替换后需重建托盘图标，此项纳入 M2 验证。
- manifest 解析与资源校验放在独立模块，并有单元测试：缺字段、非法 JSON、路径穿越、超出限制、类型伪装、槽位重复、版本不兼容。
- 局部替换记录写入设置项 skinOverrides（皮肤 id、槽位 id、文件名）；素材文件与设置文件分目录存放。设置的导出文件不含素材图片，导出时给出提示。

### 16.9 里程碑调整

- M2：完成素材仓库层、内置皮肤的素材槽位声明、设置页的「替换图片」与「恢复默认」。
- M3：风格包与素材包的导入、校验、预览、试用、卸载；此项使 M3 增加约 1 周。
- M5（P2）：L3 自由布局、L4 动画。

## 17. 多地区与多语言（新增，补充并优先于 1.3、第 3 章、4.4、第 6 章、第 7 章的对应条款）

### 17.1 目标与范围

- 产品面向全球用户。「地区」决定节假日数据、默认的每周工作日、默认币种；「语言」决定界面文字与数字日期格式。两者独立设置，例如在日本工作的中文用户，语言选中文，地区选日本。
- 语言：v1 支持简体中文与 English（P0）；第二批为繁體中文、日本語、한국어、Español、Deutsch、Français、Português (Brasil)、Русский（P1）；从右到左的语言（العربية、עברית）列为 P2，但界面从 v1 起按可镜像方式开发。
- 地区：建议首批覆盖中国大陆、中国香港、中国台湾、美国、加拿大、英国、日本、韩国、新加坡、澳大利亚、德国、法国（P0），其余国家为 P1；最终清单以 17.2 的数据源评估结果为准。
- 不做：农历、伊斯兰历、希伯来历等非公历的输入与显示，节假日只使用数据源提供的公历日期；跨零点的夜班仍不支持。

### 17.2 节假日数据（多地区）

**统一数据模型**

| 字段 | 说明 |
| --- | --- |
| region | 地区代码，国家级如 CN、US，子地区如 US-CA、DE-BY |
| date | 公历日期 |
| names | 名称的多语言映射，至少包含本地语言名称 |
| type | 休息日、补班日、观察日（节日落在休息日时顺延的实际休息日，以数据源给出的日期为准） |
| source、updatedAt | 数据来源与更新时间 |

**来源与分发策略**

- 构建期流水线从多个开源或官方来源抓取数据，校验后规整为上表的统一 JSON，发布到自有的静态分发地址；客户端只从该地址下载规整后的数据，运行时不直接依赖任何第三方接口，避免接口变更、限流与格式不一致。
- 中国大陆沿用 holiday-cn；其他地区的候选来源（如 Nager.Date 等开源或官方数据）需评估覆盖国家数、更新及时性、许可证，评估结论作为 M0 的输入。
- 隐私：客户端请求只带地区代码与年份，不带任何用户设置。

**内置与更新**

- 安装包内置首批地区的当年与次年数据；其他地区在首次选择时联网下载并缓存。
- 每日最多检查一次更新，失败时静默使用缓存；数据缺失时沿用第 6 章的降级规则，并标注「节假日数据未更新」。

**子地区与覆盖**

- 地区选择为两级：国家，再选子地区（可选）；没有子地区数据时只使用国家级假日。
- 用户手动覆盖某日为工作日或休息日、自定义假期，沿用第 6 章与 4.5。
- 假日名称优先使用当前界面语言，缺失时回退到本地名称，再回退到英文。

### 17.3 每周工作日（P0，取代原 P1 的自定义工作日规则）

- 设置页提供 7 个复选框，选择一周中哪些天为工作日；默认值由所选地区提供，具体值以数据为准，不在文档中写死。
- 影响范围：工作日判定、当月应出勤天数、下次放假、发薪日调整。4.5 的「周末算放假」改称「每周休息日算放假」。
- 一周起始日随语言与地区取默认值，用户可改，只影响设置页展示，不影响计算。
- 每个工作日使用同一组上下班时间（P0）；每个工作日不同的时间（如某天提前下班）与大小周轮换为 P1。

### 17.4 发薪规则（扩展 4.4）

| 项目 | 选项 |
| --- | --- |
| 发薪周期 | 每月固定日（P0）、每月最后一个工作日（P0）、每月两次如 15 日与月末（P0）、每两周（P1，需基准日期）、每周（P1，需指定星期） |
| 遇休息日的调整 | 顺延到下一个工作日（默认，对应已确认决策）、提前到上一个工作日、不调整 |

- 调整方式的默认值可由地区提供，用户可修改。
- 每月两次时，「距离发薪」取两次中较近的一次。
- 每两周以基准发薪日起每 14 天一次，同样应用休息日调整。
- 「本月已赚」的口径不变，仍按工作日实时累计，与发薪周期无关。

### 17.5 薪资与币种（取代 currencySymbol）

- 薪资类型：月薪（P0）、年薪（P0，按 12 等分换算为月薪）、时薪（P1，每秒薪资 = 时薪 ÷ 3600，仅在工作时段累计，不使用应出勤天数）。
- 币种使用 ISO 4217 代码（如 CNY、USD、JPY），默认值由地区提供；符号、千分位、小数点与符号位置由本地化格式库生成，不手写。
- 显示精度默认取该币种的最小货币单位位数（CNY、USD 为 2 位，JPY 为 0 位），用户可在 0 到 4 位之间调整，以便在低面额币种下看到逐秒增长。
- 税前与税后沿用 4.3 的双输入；各国税制不同，应用不做任何税务计算。
- 不做汇率换算。

### 17.6 时区与夏令时

- 工作时区默认跟随系统；可固定为某个 IANA 时区（如远程办公时按公司所在地），固定后即使用户出差，上下班、薪资与倒计时仍按该时区计算。
- 夏令时：日薪 = 当月月薪 ÷ 当月应出勤天数，不随当日实际时长变化；当日已赚 = 日薪 × 已工作秒数 ÷ 当日有效总秒数，其中当日有效总秒数按该日实际经过时间计算。因此切换日当天每秒薪资略有不同，但日薪与月累计不受影响。此条款覆盖第 3 章中对每日有效工作秒数的固定写法。
- 切换时刻附近不存在或重复出现的本地时间，按时区库规则处理，并有单元测试覆盖。
- 生命倒计时的出生时刻按出生时区解释，默认等于当前工作时区，可单独指定（P1）。
- 时区规则会随各国政策变化，核心库使用带更新机制的时区数据，不手写偏移。

### 17.7 多语言与本地化

- 语言设置：跟随系统（默认）或手动选择，切换即时生效，无需重启；语言选项用各语言自己的名称显示（如 日本語）。
- 所有界面文字走本地化资源（ARB 文件，flutter gen-l10n 生成），禁止硬编码，禁止拼接句子；带数字的文案使用 ICU 复数与参数占位（如英文的 1 day 与 2 days），中文、日文也走同一机制。
- 日期、时间、数字、货币按语言区域格式化；倒计时的 hh:mm:ss 格式保持统一，不随语言变化。
- 数字字符默认使用阿拉伯数字 0 到 9；使用本地数字字符作为设置项（P2）。
- 字体使用系统字体回退链，保证 CJK 与拉丁字符都能显示；倒计时数字仍要求等宽数字。
- 布局：窗口与文字区域自适应文案长度（如德语文案更长），超长文本截断并在固定显示状态下可展开；皮肤布局模板必须支持文案长度变化与从右到左镜像，数字与单位在镜像下方向正确。
- 皮肤与资源包内不含写死文字，标签文字来自应用的本地化资源；风格包可选携带 locales 目录覆盖文字（P2）。
- 托盘菜单、通知、首次引导、错误提示全部本地化。
- 首次启动根据系统语言与地区推荐语言与地区，用户可修改。
- 翻译流程：以英文为基准语言，提供校验脚本，发现缺失 key、占位符不一致、复数形式缺失时 CI 失败。
- 上架时，应用商店的文案与截图按语言本地化。

### 17.9 对核心库的要求（与实现语言无关）

- 核心接口的输入新增 IANA 时区 ID 与所选地区的节假日数据；时区计算必须使用带规则的时区库，不接受「固定 UTC 偏移」作为唯一输入。
- 选型：使用 Rust 的 jiff 或 chrono-tz，M0 评估后二选一。时区数据库随应用版本更新，M0 评估是否支持独立更新。
- 共享测试数据（JSON）新增用例：各地区不同周末、夏令时切换日、币种最小单位、每月两次发薪、提前与顺延、观察日。
- 核心库实现语言已确定为 Rust（见第 18 章）。多地区与时区使核心逻辑更复杂，一份核心三端共用的价值随之提高，但时区与夏令时的边界用例也更多，共享测试数据更不可缺。

## 18. Rust 核心库与手机端规划（新增，补充并优先于 13.1 至 13.4 中涉及核心库的条款）

### 18.1 决策与边界

- 核心计算库使用 Rust，一份代码供桌面端 Flutter 应用、iOS 小组件、Android 小组件共用。
- 理由：手机小组件是确定目标；小组件运行在没有 Flutter 引擎的独立环境中，需要自己完成计算，用户长期不打开应用也不能过期；多地区与时区使规则复杂，单一实现可避免三端结果不一致。
- 边界：Rust 核心只做纯计算（日历、薪资、倒计时、时区），不做网络、界面、存储、窗口。节假日数据的下载、设置的读写由宿主端（Flutter 或原生）完成，再传入核心。

### 18.2 工程结构

```
countdown/
├─ core/                    Rust workspace
│   ├─ crates/engine/       唯一业务实现：calendar、salary、life、tz、compute、timeline
│   ├─ crates/ffi/          接口层：UniFFI 定义，供 Swift 与 Kotlin 调用
│   └─ testdata/            共享测试数据（JSON），所有端共用
├─ app/                     Flutter 应用
│   ├─ rust_bridge/         flutter_rust_bridge 生成的 Dart 绑定
│   ├─ platform/            窗口、托盘、热键、原生通道
│   ├─ state/ ui/
├─ ios/Widget/              SwiftUI 小组件（手机阶段）
└─ android/widget/          Kotlin 小组件（手机阶段）
```

- engine 是唯一的业务实现；flutter\_rust\_bridge 与 UniFFI 两个接口层都只是薄封装，不得包含业务逻辑。

### 18.3 核心接口（取代 13.4）

| 函数 | 作用 |
| --- | --- |
| compute(settings, holidays, now, timeZoneId) | 返回当前时刻的完整快照 |
| timeline(settings, holidays, start, stepSeconds, count) | 返回一串未来时刻的快照，供 iOS WidgetKit 与 Android 小组件预排显示 |
| validate\_settings(settings) | 校验设置，返回错误列表 |
| api\_version() | 返回接口版本号，用于宿主与核心的兼容检查 |

- 核心不读取系统时钟与系统时区，时间以 UTC 毫秒加 IANA 时区 ID 的形式由宿主传入。
- 设置、节假日数据、快照均可序列化为 JSON，作为共享存储与测试数据的统一格式。
- 金额在核心内用十进制类型（rust\_decimal）计算；对外同时返回精确值与按 moneyPrecision 向下截断后的值，均为十进制字符串。宿主端只负责本地化排版，不做任何金额运算。
- 快照新增 nextChangeAt 字段，表示当前快照的有效截止时刻，供小组件安排下次刷新。
- 所有接口返回结果类型，任何输入都不得导致崩溃；接口边界捕获 panic 并转为错误，因为跨语言调用中的 panic 会终止整个进程。
- 时区数据使用内置数据库（jiff 或 chrono-tz 自带），iOS 与 Android 上不依赖系统时区数据文件，随应用版本更新。

### 18.4 构建与分发

- 目标平台：Windows x64、macOS（arm64 与 x86\_64）、iOS（真机与模拟器，打包为 xcframework）、Android（arm64-v8a、armeabi-v7a、x86\_64，由 cargo-ndk 构建）。
- 桌面端用 flutter\_rust\_bridge 的工程模板集成构建，一条命令完成，不要求开发者手动编译 Rust。
- CI：按平台矩阵构建，缓存 Rust 目标与依赖；engine 版本与 api\_version 保持一致；macOS 的公证流程需覆盖随应用分发的动态库。
- 体积目标：单平台核心库发布版不超过 2MB（开启 LTO 与符号裁剪，估算值，M0 实测）。
- iOS 小组件扩展内存限制严格，调用核心后的常驻内存增量目标不超过 5MB（估算值，M0 实测）。

### 18.5 手机端与小组件规划（v1 之后）

**阶段**：v1 为桌面端；之后做手机应用（Flutter，复用同一核心）与手机小组件。

| 小组件阶段 | 内容 | 刷新方式 |
| --- | --- | --- |
| 阶段 1：倒计时类 | 距离下班或上班、放假、发薪、退休 | 目标时刻由核心算出，由系统自带的计时组件走秒（iOS 的计时文本样式，Android 的 Chronometer），无需频繁刷新 |
| 阶段 2：薪资 | 今日已赚、本月已赚 | 约每分钟更新，界面明确标注；iOS 用核心的 timeline 预排，Android 用闹钟或后台任务触发 |
| 阶段 3（可选） | iOS 实时活动 | 受系统时长限制，需先实测能否覆盖整个工作日，在此之前不承诺 |

- 小组件独立计算：读取共享存储中的设置与节假日数据，调用核心计算，不依赖主应用正在运行。iOS 通过 App Group 共享，Android 在同一应用内共享。
- 共享数据格式与第 17 章的设置、节假日数据一致，由主应用写入，小组件读取。
- 节假日数据更新：主应用与小组件都可以联网更新（iOS 在获取时间线的回调中，Android 通过后台任务），主应用长期不开启时作为兜底；失败时按 17.2 降级并标注。
- 刷新限制写入界面与说明文案：手机小组件上薪资不是逐秒增长。国内部分安卓厂商会限制后台运行，需提示用户加入白名单。
- 小组件需要原生开发：iOS 为 SwiftUI，Android 为 Glance 或 RemoteViews；估计每个平台 2 至 3 周，含工程配置与签名，视团队熟悉程度而定。

### 18.6 对已有章节的修订说明

- 13.2：「金额计算 decimal」「时间注入 clock」两项取消，业务计算全部在 Rust 核心内完成，Flutter 端不做金额运算；其余依赖不变。
- 13.3 与 13.4：分别以 18.2 与 18.3 为准；第 10 章与 14 至 17 章中的验收用例整理为共享 JSON 测试数据，由 Rust 单元测试加载，作为合入门禁。
- 13.5 计时：定时器仍在 Flutter 端，每秒调用一次 compute；窗口隐藏时暂停的规则不变。
- 第 14 章长按预览：预览窗预创建，按下时只调用一次 compute 刷新，仍须满足 100ms 内可见。
